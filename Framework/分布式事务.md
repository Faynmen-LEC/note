# 消息表

## 本地消息表

1. **写本地事务**：在同一个本地数据库事务中，执行业务操作（如创建订单），同时向“本地消息表”插入一条状态为 `Pending`（待发送）的消息记录。
2. **后台轮询**：后台定时任务（如 C# 的 `BackgroundService`）定期扫描消息表，捞出 `Pending` 状态的消息。
3. **发送MQ**：将消息发送到 MQ。
4. **更新状态**：MQ 发送成功后，将消息表中的状态更新为 `Sent`（已发送）；如果失败则保持 `Pending` 等待下次重试。

## MQ消息表

利用 MQ 自身(RocketMQ)提供的“半消息（Half Message）”机制，将消息表“搬”到了 MQ 内部。

1. **发送半消息**：业务系统先向 MQ 发送一条“半消息”（此时消费者不可见）。
2. **执行本地事务**：MQ 返回半消息发送成功后，执行本地业务操作（如创建订单）。
3. **提交/回滚**：根据本地事务的执行结果，向 MQ 发送 `Commit`（提交，消费者可见）或 `Rollback`（回滚，丢弃消息）。
4. **回查机制**：如果 MQ 长时间没收到 Commit/Rollback（比如应用宕机），MQ 会主动回调业务系统的“回查接口”，检查本地事务是否成功。

## Outbox+MQ

1. **写本地事务**：与本地消息表完全一致，业务操作和写 Outbox 表在同一个本地事务中完成。
2. **CDC 监听 (改进的核心)**：不再由应用代码去写 `SELECT` 轮询。而是使用 CDC 工具（如 **Debezium**）直接监听 SQL Server 的事务日志（Transaction Log）。（用内存/Redis 队列取代）
3. **发布到 MQ**：CDC 工具一旦捕获到 Outbox 表有 `INSERT` 操作，立刻将变更数据推送到 MQ（如 Kafka / RabbitMQ）。
4. **清理数据**：后台定时任务清理已经发送的 Outbox 记录（或者通过 TTL 自动过期）。
